# 系统职责与接口草案

Phase 1 的实际入口是 `src/core/game.ts` 中的 `createRun`、`dispatch` 和 `step`，运行类型位于 `src/core/types.ts`。下文保留后续扩展的接口意图。

## 单向数据流

用户输入 → 类型化命令 → 状态/阶段校验 → 系统原子处理 → 新状态和事件 → 场景/UI/音频表现。

表现层只读游戏快照，通过命令请求改变规则状态。单位生命、资源、卡牌区和地图占地不由 UI 直接修改。规则系统之间通过定义好的状态和接口协作，避免随意互调或共享可变全局变量。

## 共同类型

| 类型 | 必须表达的内容 |
| --- | --- |
| `RunState` | 局 ID、王国、种子/随机状态、阶段、模拟 tick、地图、资源、卡牌区、建筑/单位、波次、遗物和局内效果 |
| `MetaProgress` | 已解锁内容、永久进度与版本；独立于单局 |
| `GamePhase` | 菜单、备战/建设、战斗、奖励、事件、胜利、失败；暂停保留可恢复的前状态 |
| `Command` | 明确操作类型、目标 ID/位置和参数，不携带任意脚本 |
| `CommandResult` | 成功/失败、稳定错误码、可解释原因、生成事件；失败不保留半完成副作用 |
| `GameEvent` | 有类型的放置/消费/伤害/死亡/波次/奖励等事实；需确定顺序，表现订阅者只负责呈现 |
| `ContentCatalog` | 校验后的卡牌、建筑、单位、敌人、波次、王国、事件和遗物定义及内容版本 |
| `SaveEnvelope` | schema/content 版本、局内/局外数据、随机状态、有效性信息 |

资源包含 `gold`、`food`、`wood`、`mana`。位置采用整数格坐标；渲染像素坐标不能成为规则的权威坐标。单位 ID/建筑 ID 唯一且可序列化。

## 模块接口意图

以下函数名表达职责，并非已经存在的 API。

| 模块 | 输入/职责 | 输出与约束 |
| --- | --- | --- |
| `StateManager` | `dispatch(command)`、`step(fixedDt)` | 控制阶段和命令许可；维护权威状态与有序事件 |
| `CardSystem` | 抽牌、选牌、校验/使用、升级、移除 | 合法区间/条件/费用/实际效果同步更新；规则失败不耗卡 |
| `BuildingSystem` | `canPlace(defId, tile)`、放置、升级、重算相邻效果 | 检查尺寸/边界/占地/位置条件；更新占地/导航版本和效果，不重复叠加 |
| `EconomySystem` | `canAfford(cost)`、事务支出、收入、容量、维持 | 不出现非法负数/重复扣费；不足或超限按明确规则处理 |
| `CombatSystem` | 固定步长、合法目标、伤害、弹道、死亡 | 确定性处理攻击冷却、无效目标、范围效果和生命归零；不调用渲染/浏览器计时 |
| `Navigation` | 网格、阻挡版本、起点与目标 | 路径或有原因的不可达结果；不可达时交战/选目标由战斗规则决定，禁止穿墙 |
| `WaveSystem` | 请求开战、生成计划、监听存活/城堡状态 | 避免重复生成；明确胜负和结算顺序；结算只执行一次 |
| `RoguelikeSystem` | 随机流、奖励池、解锁条件、选择 | 可复现且有限的奖励/事件/遗物；选择只能提交一次 |
| `SaveManager` | 编解码、校验、迁移；通过存储适配器读写 | 保存纯数据，拒绝损坏/未知未来版本；错误不覆盖旧有效进度 |
| 场景/UI | 快照、事件、输入与视口 | 表现、悬停与反馈；不自行判定伤害/费用/奖励 |

## 关键协作约定

- 放置/用牌/升级先做完整预检，再一次提交费用和状态；失败必须原样保留关键资源及卡牌。
- 构筑、地图、奖励与战斗可使用独立派生随机流，避免新增视觉随机影响奖励；存档保存必需随机状态。
- 战斗步长、伤害/防御/冷却单位、目标平局排序在首轮实现时明确并测试；不能用帧率隐式定义攻速。
- 存档不序列化 Phaser 对象、DOM、事件处理器、计时器或闭包。局外/设置/调试有独立键和明确版本。
- 导航、碰撞、占地和射程共享坐标约定；建筑变化触发导航更新。敌人不可达、只剩不可攻击目标和战斗停滞均有测试场景。
- 事件命名、公共类型和数据 schema 变更由一位负责人集成；并行任务先对齐接口，避免多 Agent 同改核心文件。
